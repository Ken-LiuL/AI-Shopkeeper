## 数据源全景图

牵牛花 (qnh.meituan.com) 作为多渠道（美团/饿了么/京东到家）聚合 SaaS，可获取以下数据类别：

| # | 数据类别 | 牵牛花模块 | 说明 |
|---|---------|-----------|------|
| 1 | **经营数据概览** | 数据首页 | 日/周/月维度的营收、订单、客单价、毛利等 |
| 2 | **实时数据** | 实时看板 | 当日实时订单数、营收 |
| 3 | **订单管理** | 订单列表/详情 | 订单状态、金额、商品明细、配送费 |
| 4 | **商品管理** | SPU/SKU列表 | 商品主数据、价格、渠道状态、图片 |
| 5 | **库存管理** | 库存查询/库存流水 | 实时库存、可用/锁定库存、出入库流水 |
| 6 | **流量分析** | 商品流量 | 曝光、点击、下单、转化率（按商品×渠道×日期） |
| 7 | **评价管理** | 评价列表 | 评分、评价内容、商家回复 |
| 8 | **客服IM** | 在线客服/消息 | 买家消息、自动回复、会话记录 |
| 9 | **客户/消费排行** | 客户管理 | 客户画像、复购率、消费金额排行 |
| 10 | **营销活动** | 活动管理 | 满减、折扣、秒杀、优惠券、活动效果 |
| 11 | **配送管理** | 配送/履约 | 配送状态、超时率、骑手信息、自配送 |
| 12 | **财务/结算** | 财务对账 | 渠道结算、扣费明细、佣金、活动分摊 |
| 13 | **门店设置** | 门店管理 | 营业时间、配送范围、门店信息 |
| 14 | **商品排名** | 数据分析 | 商品销量/销售额排行 |
| 15 | **渠道对比** | 数据分析 | 各渠道（美团/饿了么/京东）对比分析 |
| 16 | **退款/售后** | 售后管理 | 退款原因、退款率、缺货退款 |
| 17 | **商品分类/标签** | 商品管理 | 前台分类、智能标签 |
| 18 | **助手/任务** | 经营助手 | 待处理任务、经营建议 |

## 已覆盖 & 已利用 ✅

### 1. 经营数据概览 ✅
- **Syncer**: `MetricsSyncer` → `qnh_daily_metrics` 表
- **字段覆盖**: 有效订单额/数、客单价、毛利、实付额、包装费、配送费、客户数、动销率、超时率、缺货退款率、周转天数、缺货损失、渠道分布
- **下游使用**:
  - `DailyReportService` — 生成日报（营收、订单数、环比/同比）
  - `Alert Agent` — 异常检测输入数据
  - `api/dashboard.py` — 仪表盘展示
  - `api/analytics.py` — 分析 API
- **评价**: 🟢 覆盖全面，利用充分

### 2. 订单管理 ✅
- **Syncer**: `OrderSyncer` → `qnh_orders` 表
- **字段覆盖**: 订单ID、渠道、门店、总额、实付、状态、下单时间、配送费、包装费、客户手机尾号、商品明细(JSONB)
- **下游使用**:
  - `Bundle Agent` — FP-Growth 关联规则挖掘（基于订单商品共现）
  - `DailyReportService` — 热销/滞销统计
  - `ReplenishmentService` — 日均销量计算→安全库存
  - `FeedbackLoopService` — 选品效果追踪
  - `api/orders.py` — 订单查询 API
- **评价**: 🟢 核心数据，利用充分

### 3. 商品管理 ✅
- **Syncer**: `ProductSyncer` → `qnh_products` 表
- **字段覆盖**: SPU/SKU ID、名称、条码、品类、品牌、规格、单位、成本价、零售价、渠道价(JSONB)、状态、渠道状态、图片
- **下游使用**:
  - `Selection Agent` — 库存分析子节点
  - `Customer Service Agent` — GraphRAG 商品检索
  - `Listing Agent` — 标品匹配
  - `PricingService` — 价格分析
  - `ReplenishmentService` — 补货建议
  - `api/products.py` — 商品 API
- **评价**: 🟢 主数据，全链路使用

### 4. 库存管理 ✅
- **Syncer**: `InventorySyncer` → `qnh_inventory` 表
- **字段覆盖**: SPU/SKU、条码、商品名、当前库存、可用库存、锁定库存、成本价、库存价值、仓库
- **增量策略**: 通过库存流水 API 识别变化 SKU，再拉最新库存
- **下游使用**:
  - `Alert Agent` — 缺货预警（stockout_urgent/warning）
  - `ReplenishmentService` — 安全库存 vs 当前库存
  - `Selection Agent` — 库存健康度分析
  - `api/replenishment.py` — 补货 API
- **评价**: 🟢 高频同步(30min)，利用充分

### 5. 流量分析 ✅
- **Syncer**: `TrafficSyncer` → `qnh_traffic` 表
- **字段覆盖**: 日期、渠道、SPU、商品名、曝光数、点击数、点击率、下单数、转化率
- **下游使用**:
  - `Alert Agent` — 曝光下降(exposure_drop)、转化率下降(conversion_drop) 异常检测
  - `api/analytics.py` — 流量分析 API
- **评价**: 🟢 覆盖完整

### 6. 评价管理 ✅
- **Syncer**: `ReviewSyncer` → `qnh_reviews` 表
- **字段覆盖**: 评价ID、订单ID、渠道、评分、内容、商家回复、评价时间
- **下游使用**:
  - `api/reports.py` — 报告生成
  - Knowledge Graph — 商品评价关联
- **评价**: 🟡 同步了但 Agent 层直接使用较少（见下方 ⚠️ 部分）

### 7. 竞品数据 ✅
- **Syncer**: `CompetitorSyncer` → `competitor_products` / `competitor_stores` / `competitor_keywords`
- **数据源**: 美团 H5 移动端搜索（非牵牛花后台 API）
- **字段覆盖**: 商品名、价格、月销量、店铺名、热搜词
- **下游使用**:
  - `Selection Agent` — 竞品分析子节点、缺品识别
  - `PricingService` — 竞品均价对比
  - `Alert Agent` — 竞品价格变动/缺货机会检测
  - `DailyReportService` — 竞品动态
- **评价**: 🟢 虽非牵牛花直接 API，但数据利用充分

## 已覆盖但未充分利用 ⚠️

### 1. 评价数据 — 仅存储、未深度分析 ⚠️
- **现状**: `ReviewSyncer` 同步了评分、内容、回复，存入 `qnh_reviews`
- **缺失利用**:
  - ❌ 未做 NLP 情感分析/关键词提取
  - ❌ 评价内容未输入给 Customer Service Agent 做话术优化
  - ❌ 未统计差评率趋势、未触发差评预警
  - ❌ 未自动生成评价回复建议
  - ❌ 未关联到商品知识图谱（kg_products 缺评价摘要字段）
- **影响**: 差评反应滞后，客服缺乏评价上下文，错失口碑管理机会

### 2. 实时数据 — 有 API 但未定时拉取 ⚠️
- **现状**: `QNHClient.get_realtime_data()` 方法已实现，但无对应 Syncer
- **缺失利用**:
  - ❌ 无实时数据存储表
  - ❌ 无实时异常告警（如当前时段订单骤降）
- **影响**: 只能做 T+1 分析，无法做日内实时经营预警

### 3. 商品销量排行 — 有 API 但未持久化 ⚠️
- **现状**: `QNHClient.get_product_sales_ranking()` 已实现，但无 Syncer 定期拉取
- **缺失利用**:
  - ❌ 排行数据未存表
  - ❌ Selection Agent 依赖 order_items 聚合而非直接排行数据
- **影响**: 次要问题，可通过订单聚合间接获得

### 4. 数据趋势 — 有 API 但未独立存储 ⚠️
- **现状**: `QNHClient.get_data_trend()` 已实现，`MetricsSyncer` 只用了 overview 而非 trend
- **缺失利用**:
  - ❌ 趋势数据未单独存储（虽然可由 daily_metrics 按日聚合还原）
- **影响**: 低优先级，当前 daily_metrics 可替代

### 5. 渠道分布数据 — 存了但未深度利用 ⚠️
- **现状**: `qnh_daily_metrics.channel_distribution` 字段已存储
- **缺失利用**:
  - ❌ 无渠道健康度对比分析 Agent
  - ❌ 未做渠道差异化定价建议
  - ❌ 日报中未展示渠道分布变化
- **影响**: 无法针对弱势渠道做精细化运营

### 6. 库存流水 — 只用于识别变化，未分析 ⚠️
- **现状**: `InventorySyncer` 调用 `STOCK_FLOW_API` 但只提取 SKU ID，不存储流水记录
- **缺失利用**:
  - ❌ 出入库流水未持久化
  - ❌ 无法分析库存损耗、盘亏
  - ❌ 无法追溯库存变动原因
- **影响**: 库存分析缺少"为什么变"的维度

## 完全缺失 ❌

### 1. 客服IM / 在线消息 ❌
- **牵牛花能力**: 聚合多渠道买家消息，支持自动回复规则
- **现状**: Customer Service Agent 是独立设计的（基于知识图谱 + LLM），但**不从牵牛花拉取真实买家消息**
- **缺失**:
  - ❌ 无买家消息同步
  - ❌ 无真实对话历史分析
  - ❌ 无买家消息量/响应时间统计
- **影响**: 客服 Agent 是"空转"状态——架构完整但无真实数据流入，`cs_analytics` 表大概率为空

### 2. 客户/消费排行 ❌
- **牵牛花能力**: 客户复购分析、消费金额排行、新老客占比
- **现状**: 无相关 Syncer 或 API
- **缺失**:
  - ❌ 无客户复购率数据
  - ❌ 无新老客比例趋势
  - ❌ 无高价值客户识别
  - ❌ 无客户留存分析
- **影响**: 无法做客户分层运营、VIP维护、流失预警

### 3. 营销活动 ❌
- **牵牛花能力**: 各渠道活动配置、满减/折扣/秒杀/优惠券管理、活动效果追踪
- **现状**: 无相关 Syncer
- **缺失**:
  - ❌ 不知道当前在跑哪些活动
  - ❌ 无法评估活动 ROI
  - ❌ Alert Agent 的 `is_promotion` 字段（sales_history 表）无数据源
  - ❌ 定价建议无法考虑活动叠加影响
- **影响**: 严重——所有涉及"促销"的分析都是盲区。Prophet 预测缺少促销特征，预警归因不准

### 4. 配送/履约 ❌
- **牵牛花能力**: 配送状态追踪、超时率统计、骑手管理
- **现状**: `qnh_daily_metrics` 中有 `overtime_rate` 但只是一个聚合数字，无订单级配送数据
- **缺失**:
  - ❌ 无订单级配送状态
  - ❌ 无配送时效分析
  - ❌ 无超时原因分析
  - ❌ 无骑手绩效数据
- **影响**: 无法优化履约体验，配送差评无法归因

### 5. 财务/结算 ❌
- **牵牛花能力**: 各渠道结算单、扣费明细（佣金/配送费/活动分摊）、对账
- **现状**: 无相关 Syncer
- **缺失**:
  - ❌ 不知道实际到手金额
  - ❌ 无佣金率分析
  - ❌ 无活动费用分摊明细
  - ❌ `net_profit` 字段可能不准（缺扣费数据）
- **影响**: 毛利/净利计算可能失真，盈亏分析不完整

### 6. 退款/售后 ❌
- **牵牛花能力**: 退款单列表、退款原因分类、缺货退款统计
- **现状**: `qnh_daily_metrics` 有 `stockout_refund_rate` 聚合值，但无退款明细
- **缺失**:
  - ❌ 无退款订单明细
  - ❌ 无退款原因分布（缺货/质量/配送/其他）
  - ❌ 无退款率趋势追踪
- **影响**: 缺货退款只有比率无法追到具体商品，质量问题无法识别

### 7. 门店设置/营业信息 ❌
- **牵牛花能力**: 营业时间、配送范围、公告等
- **现状**: 硬编码 `DEFAULT_POI_IDS` 和 `DEFAULT_TENANT_ID`
- **缺失**:
  - ❌ 营业时间未动态获取
  - ❌ 配送范围未同步
- **影响**: 低优先级，变更频率低

### 8. 经营助手/任务 ❌
- **牵牛花能力**: 平台推送的待办任务、经营建议
- **现状**: `QNHClient.get_poi_tasks()` 已实现但未被任何 Syncer 或 Agent 使用
- **缺失**:
  - ❌ 平台任务未同步
  - ❌ 平台建议未纳入决策
- **影响**: 可能错过平台激励、合规要求

## 建议优先级

按 ROI（实现难度 vs 产品价值）排序：

### P0 — 立即补充（ROI 最高）

**1. 🔴 营销活动数据同步**
- 预估工作量: 2-3天
- 理由: 当前 Prophet 和 Alert 的"促销"特征全是空的，导致每次大促都会误报异常。补上后 Prophet 准确度预计提升 20%+
- 实现: 新增 `PromotionSyncer`，拉取活动列表 + 效果数据，存入 `qnh_promotions` 表，回填 `sales_history.is_promotion`

**2. 🔴 客服IM消息接入**
- 预估工作量: 3-5天
- 理由: Customer Service Agent 整个链路已完善（意图识别→GraphRAG→回复生成），但没有真实消息输入，等于未上线
- 实现: 对接牵牛花消息 API 或 WebSocket，将买家消息路由给 CS Agent

### P1 — 本月完成

**3. 🟠 退款/售后明细同步**
- 预估工作量: 1-2天
- 理由: `stockout_refund_rate` 已有聚合值但追不到 SKU，补上后可精准补货 + 质量预警
- 实现: 新增 `RefundSyncer`，存入 `qnh_refunds` 表

**4. 🟠 财务/结算数据同步**
- 预估工作量: 2-3天
- 理由: 当前 `net_profit` 可能不含渠道扣费，利润分析失真
- 实现: 新增 `SettlementSyncer`，拉取结算单 + 扣费明细

**5. 🟠 评价深度利用**
- 预估工作量: 2天
- 理由: 数据已有，只需加 Agent 节点
- 实现: 增加评价情感分析节点 → 差评预警 → 自动回复建议

### P2 — 下个迭代

**6. 客户数据同步** — 新增 `CustomerSyncer`，支撑 RFM 分析
**7. 配送数据同步** — 新增 `DeliverySyncer`，支撑履约分析
**8. 实时数据定期拉取** — 每5分钟拉一次，支撑日内预警

### P3 — 按需

**9. 库存流水持久化** — 扩展 `InventorySyncer`
**10. 门店设置同步** — 低频，手动即可
**11. 经营助手任务** — 对接 `get_poi_tasks()` 已有的 API

## 总结

| 维度 | 数量 | 占比 |
|------|------|------|
| ✅ 已覆盖且利用充分 | 7 | 39% |
| ⚠️ 已覆盖但未充分利用 | 6 | 33% |
| ❌ 完全缺失 | 5 | 28% |

**当前数据利用率约 39%**（按数据类别计）。最大的盲区是**营销活动**和**客服IM**——前者影响所有分析模型的准确性，后者让 Customer Service Agent 这个最完善的模块无法投入实战。建议优先补这两个。
